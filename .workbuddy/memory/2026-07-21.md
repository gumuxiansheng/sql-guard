## 新增文件级检查：编码 UTF-8(无BOM) + 换行符 LF

**需求**：新增文件检查规则——编码格式必须为 UTF-8（无 BOM）= 必须(error)；换行符应为 LF = 提示(warning)。

**方案**：这是字节级文件属性检查，与基于 SQL-AST 的 Rhai 规则不同，故实现为**原生 Rust 检查器**，产出标准 `Violation` 复用现有 reporter。
- 规则号 `FILE001`(编码, 默认 error) / `FILE002`(换行符, 默认 warning)，统一分组 `file-format`
- 复用 `RuleFilter`，支持 `--exclude-rules FILE001` / `--exclude-groups file-format`
- 默认启用（现有测试 fixture 都是 LF+无BOM，不会误报）

**改动文件**：
- `src/config.rs`：新增 `FileCheckConfig`（enabled/check_encoding/check_line_ending/encoding_severity="error"/line_ending_severity="warning"），Config 加 `file_check` 字段
- `src/rule/engine.rs`：`RuleFilter` 抽出 `matches_id_group(id, group)`，供原生检查器按 id/分组复用过滤逻辑
- `src/checker/encoding.rs`（新文件）：`check_file()` + `detect_encoding_issue`（BOM 检测：UTF-8/UTF-16 LE·BE/UTF-32 LE·BE，注意 UTF-32 LE `FF FE 00 00` 须先于 UTF-16 LE `FF FE` 判断；无 BOM 则 `str::from_utf8` 校验）+ `detect_line_ending_issue`（扫描 CRLF/单独 CR，报首处行号+计数）；含 8 个单测
- `src/checker/mod.rs`：`pub mod encoding;`
- `src/main.rs`：三处调用点（脚本模式 / mapper 模式 / diff 模式，diff 模式整文件检查不做 hunk 过滤）；`generate_default_config` + `get_default_config_content` 补 `[file_check]` 段
- `sqlguard.toml.example` / `README.md`：补 `[file_check]` 说明（README 五区块→六区块）

**验证**（全部通过）：
- `cargo build --release` 通过（仅既有 dead-code 警告）
- `cargo test --release`：32 单测（含 8 encoding）+ 9 集成测试全过
- 手动 E2E：clean.sql 无误报；bom.sql→FILE001 ERROR；crlf.sql→FILE002 WARN(2行)；bom_crlf.sql→两者都触发；`--exclude-rules FILE001` 只剩 FILE002；`--exclude-groups file-format` 无违规
