# 2026-07-21

## 文件扫描行为改造：白名单 + 黑名单双重机制

**需求**：原项目递归扫描整个 target_dir 下所有子目录（包括 .git/target/node_modules 等大目录），改为只扫描配置的目录并跳过 .git 等大目录。

**方案**（用户确认）：
- 新增独立 `[scan].paths` 白名单（缺省回退到 `[structure].paths`，仍为空则扫描整个 target_dir 兜底）
- 所有递归扫描统一跳过 `[scan].exclude_dirs` 黑名单（默认含 .git/.svn/.hg/.bzr/target/node_modules/build/dist/out/.idea/.vscode）
- Mapper XML 扫描同样应用黑名单
- 目录结构校验（strict 模式）同样应用黑名单

**改动文件**：
- `src/config.rs`：新增 `ScanConfig` 结构（paths + exclude_dirs），Config 加 `scan` 字段（serde default）
- `src/checker/classification.rs`：`collect_sql_files` 改签名 `(root, scan_paths, exclude_dirs)`，按白名单扫描根列表 + 递归跳过黑名单
- `src/mapper/mod.rs`：`collect_mapper_files` 加 `exclude_dirs` 参数，`collect_xml_files` 递归时跳过黑名单
- `src/checker/directory.rs`：`check_directory_structure` 加 `exclude_dirs` 参数；**顺手修复 Windows 路径分隔符 bug**（rel_str 反斜杠统一为正斜杠，否则 strict 模式下 sql\ddl 既报 missing 又报 unexpected）
- `src/main.rs`：`run_check` 中计算 `effective_scan_paths`（scan.paths 优先 → structure.paths → 兜底整个 root）；`generate_default_config` 加 scan 字段；`get_default_config_content` 更新 toml 注释
- `sqlguard.toml.example` / `README.md`：补充 `[scan]` 配置说明

**验证**：
- 单元测试 24 passed + 集成测试 9 passed（不破坏现有行为）
- 手动验证 1：.git/target/node_modules/.vscode 下的违规 SQL 均被跳过，files_checked==2，directory_issues 不含这些目录
- 手动验证 2：`[scan].paths=["sql/ddl"]` 白名单生效，sql/legacy 被跳过；自定义 `exclude_dirs` 增加 backup 生效
- Windows 路径分隔符修复验证：sql/ddl 不再被误报为 missing/unexpected

**注意**：`run_check_diff` 走 git diff 流程，不调用 collect_* 函数，无需改动。
