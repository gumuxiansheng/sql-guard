## 修复 DDL002 primary_key_required 规则漏洞（ALTER TABLE 补建主键误报）
- 问题：原 `config/rules/ddl/primary_key_required.rhai` 仅检查 `CREATE TABLE` 是否内联主键，
  当主键通过同文件 `ALTER TABLE ... ADD PRIMARY KEY` 补建时会被误报为缺失主键（false positive）。
- 根因：AST 包装层 `src/rule/engine.rs` 的 `convert_statement` 对 `Statement::AlterTable` 丢弃了全部信息，
  未暴露 ALTER 详情（文档 §11 已注明需扩展 StmtInfo 才能支持 ALTER）。
- 改动：
  - 新增 `AlterTableInfo { table_name, adds_primary_key, drops_primary_key }`，在 `convert_statement` 中
    解析 `AlterTableOperation::AddConstraint(TableConstraint::PrimaryKey)`、`AddColumn`(列级 PK)、`DropPrimaryKey`。
  - 给 `StmtInfo` 增加 `alter_table: Option<AlterTableInfo>` 字段，并在 `build_engine` 注册
    `AlterTableInfo` 类型与 `table_name/adds_primary_key/drops_primary_key` 方法，以及 `StmtInfo::has_alter_table/alter_table`。
  - 重写规则脚本（config 与 examples 两份同步）：第一遍收集 ALTER 增删主键（按表名），
    第二遍判断每张表最终是否有主键——CREATE 无内联 PK 但同文件有 ALTER ADD PK 视为合规；
    CREATE 有 PK 但被 ALTER DROP PRIMARY KEY 移除仍报违规。
  - 同步更新 `docs/rule-scripting.md`（AlterTableInfo API）、`docs/default-rules.md`（DDL002 跨语句说明与示例）。
  - 新增 `examples/ddl/clean/create_pk_via_alter.sql` 合规样例。
  - 新增集成测试 `test_check_ddl002_alter_primary_key`（tests/integration_test.rs）。
- 验证：`cargo check` 通过；release 构建通过；手工端到端 4 文件用例（2 合规 / 2 违规）结果正确；
  集成测试 10/10 通过。
- 注：sqlparser 0.45 中 `ADD PRIMARY KEY` 解析为 `AddConstraint(TableConstraint::PrimaryKey)`，无独立 `AddPrimaryKey` 变体。

## 规则全面审计 + 修复 3 个引擎级 bug
- 实证驱动：先建临时项目（C:/tmp/rule-audit）跑当前二进制确认误报，再修，再复测。
- **DML005 column_references_qualified**（bug）：`analyze_query` 的 `ExprWithAlias` 分支用
  `!expr.to_string().contains('.')` 判未限定列，把 `COUNT(*) AS cnt`、字面量别名等函数/非列表达式
  在多表查询里全部误报。修复：仅当 `matches!(expr, Expr::Identifier(_))`（裸列）才标记。
- **DML106 union_all_preferred**（两个 bug）：(a) 对任意 `SetOperation` 都设 union=true，
  INTERSECT/EXCEPT 被当 UNION 误报；(b) `union_all = op_str.contains("ALL")` 恒为 false
  （ALL 在 set_quantifier 不在 op），真 UNION ALL 也被误报。修复：op 用 `SetOperator::Union` 判断，
  union_all 用 `matches!(set_quantifier, All | AllByName)`；新增 `intersect`/`except` 字段 +
  `is_intersect()/is_except()` 并注册。
- **DML001 no_select_all**（漏报）：`analyze_query` 只看顶层 `SetExpr::Select`，UNION 分支、
  FROM/JOIN 子查询里的 SELECT * 漏报。修复：新增递归 `query_has_wildcard/set_expr_has_wildcard`，
  整棵树识别通配符。
- 测试：新增 `test_check_rule_audit_fixes`（集成测试），覆盖上述 5 个场景；全量回归 11/11 通过。
- 文档：`docs/rule-scripting.md` 补全 SelectInfo/JoinInfo 方法列表（含 is_intersect/is_except）。
- 未修（留作后续/已知局限）：DML101 别名 JOIN 误报（需 JoinInfo 暴露 alias）、
  DML105 窗口函数 OVER(ORDER BY) 误报（需识别窗口函数）、DML102 CTE 字符串启发式脆弱（AST 未解析 WITH）、
  DML103/DML104/DML108 字符串匹配类规则天然有注释/字符串字面量误报风险。
